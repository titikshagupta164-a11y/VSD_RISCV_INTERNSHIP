# <img src="https://img.icons8.com/color/48/000000/1-circle.png" width="28"/> Integration Guide

This guide explains how to integrate the **PWM IP** into the **VSDSquadron RISC-V SoC**. The reader is assumed to be familiar with the existing **riscv.v** architecture and memory-mapped peripheral integration.

---

## Required RTL Files

- `pwm.v` : PWM IP Module
- `riscv.v` : Existing VSDSquadron SoC
- `ice40_stubs.v` : Required for simulation

---

# Step 1 : Add PWM Module

Copy **pwm.v** into the RTL directory of the SoC project.

```text
RTL/
│
├── riscv.v
├── pwm.v
├── gpio_control.v
├── clockworks.v
├── emitter_uart.v
└── ...
```

---

# Step 2 : Add PWM Output Port

Open **riscv.v** and add the PWM output port to the top-level module.

```verilog
output PWM_OUT
```

This signal is connected to the PWM output generated by the PWM controller.

---

# Step 3 : Add Address Decode

Reserve one memory-mapped address for the PWM peripheral.

```verilog
localparam IO_LEDS_bit      = 0;
localparam IO_UART_DAT_bit  = 1;
localparam IO_UART_CNTL_bit = 2;
localparam IO_GPIO_bit      = 3;
localparam IO_PWM_bit       = 4;
```

Generate the PWM select signal.

```verilog
wire pwm_sel = isIO & mem_wordaddr[IO_PWM_bit];
```

The PWM IP will now respond whenever software accesses the IO_PWM address space.

---

# Step 4 : Instantiate PWM IP

Instantiate the PWM module inside **riscv.v**.

```verilog
wire [31:0] pwm_rdata;

pwm pwm_ip (

    .clk(clk),
    .resetn(resetn),

    .sel(pwm_sel),
    .we(mem_wstrb),
    .addr(mem_addr),
    .wdata(mem_wdata),
    .rdata(pwm_rdata),

    .pwm_out(PWM_OUT)

);
```

This connects the PWM controller to the processor memory bus.

---

# Step 5 : Connect PWM Read Data

Include PWM data in the memory read multiplexer.

```verilog
wire [31:0] IO_rdata =

        mem_wordaddr[IO_UART_CNTL_bit] ? {22'b0,!uart_ready,9'b0} :
        mem_wordaddr[IO_GPIO_bit]      ? GPIO_rdata :
        mem_wordaddr[IO_PWM_bit]       ? pwm_rdata :
                                         32'b0;
```

This allows software to read the CTRL, PERIOD, DUTY and STATUS registers.

---

# <img src="https://img.icons8.com/color/48/000000/2-circle.png" width="28"/> Board-level Usage

The PWM controller produces a digital PWM waveform on the **PWM_OUT** signal. Connect this signal to an FPGA output pin or external peripheral such as an LED or motor driver.

---

## FPGA Pin Assignments

Assign **PWM_OUT** to any available FPGA output pin in the PCF file.

Example:

```text
set_io PWM_OUT 11
```

Replace pin **11** with any unused FPGA pin as required by your board design.

---

## Physical Connections

| Signal | Connect To |
|---------|------------|
| PWM_OUT | LED (through resistor), Oscilloscope, Logic Analyzer or Motor Driver |
| GND | Common Ground |

---

## Verifying PWM Output

The PWM signal can be verified using:

- Oscilloscope
- Logic Analyzer
- LED (through a current-limiting resistor)

Changing the **PERIOD** register changes the output frequency, while changing the **DUTY** register changes the duty cycle.

---

## Build and Flash Commands

Compile and program the FPGA using the standard build process.

```bash
sudo make clean
sudo make build
sudo make flash
```

---

## Firmware Integration

Define the PWM register addresses.

```c
#define IO_PWM_CTRL     64
#define IO_PWM_PERIOD   68
#define IO_PWM_DUTY     72
#define IO_PWM_STATUS   76
```

Example firmware:

```c
#include "io.h"

int main()
{
    IO_OUT(IO_PWM_PERIOD, 100);
    IO_OUT(IO_PWM_DUTY, 40);
    IO_OUT(IO_PWM_CTRL, 1);

    while (1);

    return 0;
}
```

This example configures:

- **PERIOD = 100**
- **DUTY = 40**
- **ENABLE = 1**

The PWM controller immediately begins generating a PWM waveform with a **40% duty cycle**.
